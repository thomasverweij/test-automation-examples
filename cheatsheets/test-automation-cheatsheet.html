03
Basic Test Case Boilerplate
cy docspw docs
Cypress
// cy, describe, it are globals — no import needed
// for @testing-library/cypress (used in role/label cards):
// add to cypress/support/e2e.js:
import '@testing-library/cypress/add-commands';

describe('My Suite', () => {
  beforeEach(() => {
    // runs before each test
  });

  it('should do something', () => {
    // test steps here
  });
});
Playwright
import { test, expect } from '@playwright/test';

test.describe('My Suite', () => {
  test.beforeEach(async ({ page }) => {
    // runs before each test
  });

  test('should do something', async ({ page }) => {
    // test steps here
  });
});

06
Find Element by Role
cy docspw docs
Cypress
// requires @testing-library/cypress

// by role only
cy.findByRole('navigation');
cy.findByRole('dialog');

// with accessible name (text / aria-label)
cy.findByRole('button', { name: 'Submit' });
cy.findByRole('link', { name: 'Read more' });
cy.findByRole('heading', { name: /welcome/i });

// case-insensitive name match
cy.findByRole('button', { name: /submit/i });

// common roles:
// button, link, textbox, checkbox, radio,
// combobox, listbox, option, menuitem,
// heading, banner, navigation, main,
// dialog, alert, table, row, cell, img
Playwright
// built-in — chain action after

// by role only
page.getByRole('navigation');
page.getByRole('dialog');

// with accessible name (text / aria-label)
page.getByRole('button', { name: 'Submit' });
page.getByRole('link', { name: 'Read more' });
page.getByRole('heading', { name: /welcome/i });

// exact: false for partial name match
page.getByRole('button', { name: 'Submit', exact: false });

// level for headings (h1–h6)
page.getByRole('heading', { level: 1 });

// checked state for checkboxes / radios
page.getByRole('checkbox', { checked: true });

// expanded state for dropdowns / trees
page.getByRole('combobox', { expanded: false });

// disabled state
page.getByRole('button', { disabled: true });

09
Filter Elements
cy docspw docs
Cypress
// by index
cy.get('li').eq(0);

// by text — returns all matches
cy.get('li').filter(':contains("Active")');

// preferred: scoped contains
cy.contains('li', 'Active');

// first / last
cy.get('tr').first();
cy.get('tr').last();
Timing: cy.get('li').filter() waits for at least one li to exist, then filters immediately — it does not retry waiting for matching text to appear. cy.contains('li', 'Active') is preferred: it retries until a match is found and returns the li itself.

Scope: Both :contains() and cy.contains() match text anywhere in the element's subtree — text inside a nested <span> will still match.
Playwright
// by index
await page.locator('li').nth(0).click();

// by contained text — returns all matches
await page.locator('li').filter({ hasText: 'Active' }).click();

// first / last
await page.locator('tr').first().click();
await page.locator('tr').last().click();
Timing: locator() is lazy — nothing runs until you act or assert. At that point Playwright auto-waits, so it will keep retrying until a matching li appears. Safer than Cypress's get().filter() for async content.

Scope: hasText also matches text anywhere in the element's subtree — text inside a nested <span> inside the li will still match.

⚠ Known Gotchas & Frustrations
Cypress Commands silently change the subject

Some commands replace the current subject with a different element. .contains() returns the deepest matching descendant, not the element you called it on. .find() replaces the subject entirely with the found child.

// subject becomes <span> inside li, not the <li> cy.get('li').contains('Active').click() // scoped contains keeps li as subject cy.contains('li', 'Active').click()
Cypress No real async/await — command queue only

Cypress uses an internal command queue, not real Promises. You cannot await a cy command or store its result in a variable for later use.

// ✗ does NOT work as expected const el = cy.get('input') el.type('hello') // ✓ use .then() to work with values cy.get('input').then(($el) => { cy.wrap($el).type('hello') })
Cypress Only the last command in a chain retries

In a chain like cy.get('ul').find('li').should(...), only find('li') is retried on failure. If ul doesn't exist yet when the chain runs, the whole thing fails immediately.

// ✗ if ul loads late, get() won't re-run cy.get('ul').find('li').should('have.length', 3) // ✓ target the final element directly cy.get('ul li').should('have.length', 3)
Cypress .its() and .invoke() don't retry meaningfully

.its('length') reads a value at the moment it is evaluated and does not reliably retry if the value hasn't reached the expected state yet. Pair it with a .should() to force retrying.

// ✗ may read length before list fully renders cy.get('li').its('length').should('eq', 5) // ✓ should() on the subject retries correctly cy.get('li').should('have.length', 5)
Cypress cy.intercept() — later registrations win

When multiple intercepts match the same request, the last registered one takes priority. An intercept set up in the test body silently overrides one set up in beforeEach.

// beforeEach intercept gets silently overridden beforeEach(() => cy.intercept('GET', '/api/user', { id: 1 })) it('test', () => { cy.intercept('GET', '/api/user', { id: 99 }) // wins })
Playwright Locators are strict — multiple matches throw

If a locator matches more than one element, any action (.click(), .fill(), etc.) throws an error. Cypress silently acts on the first match. You must explicitly narrow the locator.

// ✗ throws if more than one button matches await page.locator('button').click() // ✓ narrow with .first(), .nth(), or .filter() await page.locator('button').first().click() await page.locator('button').filter({ hasText: 'Save' }).click()
Playwright Fresh browser context per test — no shared state

Each test gets a new browser context by default. Cookies, localStorage, and session state are not carried over between tests. Use storageState in config to share auth state.

// ✓ share login state via storageState in config use: { storageState: 'auth.json' }
Playwright waitForNavigation() is a race condition

Calling click() then waitForNavigation() sequentially is a race — the navigation can complete before the wait is registered. Always set up the wait before triggering the action.

// ✗ navigation may finish before wait is set up await page.click('a#submit') await page.waitForNavigation() // ✓ register wait first, trigger after await Promise.all([ page.waitForNavigation(), page.click('a#submit') ])
Playwright Auto-wait doesn't cover network requests

Playwright waits for elements to be visible and stable before acting, but does not automatically wait for background network requests. A button can be clickable while the data it depends on is still loading.

// ✓ wait for a specific response await page.waitForResponse('**/api/data') // ✓ or wait until network is idle await page.waitForLoadState('networkidle')
Both Index selectors are fragile

.eq(0) / .nth(0) grab whichever element happens to be first at that moment. If a list renders incrementally or its order can change, index-based selectors produce flaky tests.

// ✗ fragile — breaks if order or rendering changes cy.get('li').eq(0).click() page.locator('li').nth(0).click() // ✓ resilient — select by stable identity cy.contains('li', 'Dashboard').click() page.getByRole('listitem', { name: 'Dashboard' }).click()
Both Hidden ≠ non-existent

Both tools distinguish between an element that is in the DOM but hidden (e.g. display:none) and one that doesn't exist at all. The error messages are different and easy to misread.

// Cypress cy.get('.modal').should('exist') // passes if hidden cy.get('.modal').should('be.visible') // fails if hidden // Playwright expect(locator).toBeAttached() // passes if hidden expect(locator).toBeVisible() // fails if hidden
